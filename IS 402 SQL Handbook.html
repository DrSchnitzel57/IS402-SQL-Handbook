How a query runs

Use it when a query errors for a reason that seems unfair, like an alias "not existing."

How it works

You write SELECT first, but Postgres runs the clauses in this order. Each step only sees what earlier steps produced.

  1. FROM / JOIN build rows
  2. WHERE drop rows
  3. GROUP BY make groups
  4. HAVING drop groups
  5. SELECT compute columns, aliases
  6. DISTINCT drop duplicates
  7. ORDER BY sort
  8. LIMIT cut
Because of this order…So
Aliases are created in SELECT (step 5)You can't use them in WHERE or HAVING. You can in ORDER BY.
Groups don't exist yet in WHERE (step 2)Totals like COUNT(*) > 3 go in HAVING.
Window functions run in SELECTFilter on them from an outer query or CTE.
Written order is fixedAlways write SELECT → FROM → JOIN → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT.

Reading data

SELECT & sorting

Use it when choosing columns, naming them, sorting, removing duplicates, or keeping the first few rows.

How it works

SELECT lists what each output row shows; FROM says where rows come from. Without ORDER BY, row order is not guaranteed. DISTINCT removes rows that are identical across every selected column.

NeedSyntax

Rename a columnRetailPrice AS price

Mixed directionsORDER BY state, price DESC

First N rowsORDER BY … LIMIT 5
Skip rowsLIMIT 5 OFFSET 10

Five most expensive products; ties broken by name

SELECT ProductName, RetailPrice AS price
FROM SalesOrdersExample.Products
ORDER BY RetailPrice DESC, ProductName
LIMIT 5;
Traps
  • DISTINCT works on the whole row. SELECT DISTINCT city, state keeps each city/state pair once.
  • LIMIT without ORDER BY returns arbitrary rows.
  • Aliases come out lowercase unless double-quoted: AS "Price".

Math & expressions

Use it when a column you need isn't stored: totals, percentages, rounded values, conversions.

How it works

Any SELECT item can be a formula. Postgres computes it once per row. The result's type follows the inputs: integer ÷ integer stays an integer and drops the decimal.

Line totals for one order

SELECT OrderNumber, ProductNumber,
       QuotedPrice * QuantityOrdered AS line_total
FROM SalesOrdersExample.Order_Details
WHERE OrderNumber = 1;
Traps
  • ROUND(col, 2) on a real/float column errors. Use ROUND(col::numeric, 2).
  • Any math with NULL returns NULL. Wrap it: COALESCE(col, 0).
  • You can't reuse an alias in the same SELECT or in WHERE. Repeat the formula.

Filtering with WHERE

Use it when you only want some rows.

How it works

WHERE tests every row and keeps it only if the condition is true. False and unknown (NULL) both drop the row.

NeedSyntax
Equal / not equal= 'Seattle'   <> 'WA'
Compare> >= < <=
In a listIN ('WA', 'OR')   NOT IN (…)
Range (both ends included)BETWEEN 100 AND 199
Starts with / ends with / containsLIKE 'A%'   '%son'   '%bike%'

Ignore caseILIKE 'a%'

AND runs before OR. Wrap OR choices in parentheses: WHERE state = 'WA' AND (city = 'Seattle' OR city = 'Bellevue').

Entertainers in two cities whose names start with J

SELECT EntStageName, EntCity
FROM EntertainmentAgencyExample.Entertainers
WHERE EntCity IN ('Seattle', 'Bellevue')
  AND EntStageName LIKE 'J%';
Traps
  • LIKE only works on text. For number ranges use BETWEEN or >=/<.
  • % is a wildcard only inside LIKE. BETWEEN 'S%' … treats it as a literal.
  • Text compares in dictionary order: 'Smith' > 'S', so BETWEEN 'S' AND 'W' misses "Wilson".
  • Quote text and dates; don't quote numbers.

Reading data

NULL & blanks

Use it when looking for missing values, or when results seem to skip rows.

How it works

NULL means "no value." It isn't 0 or blank text. Any comparison with NULL is unknown, so = NULL never matches. Only IS NULL / IS NOT NULL test it.

NeedSyntax
Has no valuecol IS NULL
Has a valuecol IS NOT NULL
Empty text (not NULL)col = ''
Missing either waycol IS NULL OR col = ''
Replace NULLCOALESCE(col, 'none')
Turn a value into NULLNULLIF(col, '')
NULL-safe comparisona IS DISTINCT FROM b

Entertainers with no web page

SELECT EntStageName
FROM EntertainmentAgencyExample.Entertainers
WHERE EntWebPage IS NULL;
Traps
  • Some "not entered" values are stored as ''. If IS NULL finds too few rows, check = '' too.
  • NOT IN (subquery) returns nothing if the subquery has a NULL. Use NOT EXISTS.
  • 'a' || NULL is NULL. CONCAT() skips NULLs instead.
  • COUNT(col), SUM, AVG ignore NULLs; COUNT(*) doesn't. DISTINCT keeps one NULL as its own value.

Full name in one column

SELECT StfFirstName || ' ' || StfLastname AS full_name,
       LENGTH(StfLastname) AS letters
FROM SchoolSchedulingExample.Staff
ORDER BY StfLastname, StfFirstName;
Traps
  • || with a NULL column makes the whole result NULL. Use CONCAT or COALESCE.
  • Comparisons are case-sensitive. Use ILIKE or UPPER(col) = 'SMITH'.
  • Cast before math: CAST(SUBSTRING(loc FROM 2) AS integer) % 2.
  • Sort by the real columns, not the combined string, when the order should be last name then first.

Dates & times

Use it when filtering by day or month, adding time, measuring gaps, or formatting dates.

How it works

Three types: date (2017-09-02), time (13:00:00), timestamp (both). Write literals as quoted text 'YYYY-MM-DD'. Math rules: date ± integer = date; date − date = days (integer); timestamp ± interval = timestamp; timestamp − timestamp = interval.

October 2017 bookings and how many days each ran

SELECT EngagementNumber, StartDate, EndDate,
       EndDate - StartDate + 1 AS days_booked
FROM EntertainmentAgencyExample.Engagements
WHERE StartDate >= '2017-10-01' AND StartDate < '2017-11-01'
ORDER BY StartDate;
Traps
  • A timestamp at noon never equals a plain date (that means midnight). Compare with ::date.
  • BETWEEN '…-01' AND '…-31' on a timestamp misses everything after midnight on the 31st.
  • date + INTERVAL turns into a timestamp. Add ::date if you want a date back.
  • EXTRACT(DOW …): 0 = Sunday. "As of today" answers change daily.

Reading data

CASE

Use it when a column depends on a condition, or you need a value the table doesn't store (labels, full names for codes, custom sort order).

How it works

CASE checks its WHEN lines top to bottom for each row and returns the first matching THEN. No match → ELSE, or NULL if there's no ELSE.

Condition form: any comparison

CASE WHEN RetailPrice >= 1000 THEN 'Premium'
     WHEN RetailPrice >= 100  THEN 'Standard'
     ELSE 'Budget'
END AS price_tier

Value form: equals only

CASE Gender
  WHEN 'M' THEN 'Male'
  WHEN 'F' THEN 'Female'
  ELSE 'Unknown'
END AS gender_name
Also works inExample
ORDER BY (custom order)ORDER BY CASE state WHEN 'WA' THEN 1 ELSE 2 END, city
Inside an aggregateSUM(CASE WHEN RetailPrice > 500 THEN 1 ELSE 0 END)
WHEREWorks, but plain AND/OR is usually clearer
Traps
  • The value form can't do < or >=. CASE score WHEN < 85 is a syntax error.
  • First match wins, so order conditions from most to least specific.
  • Every THEN must return the same kind of value (all text or all numbers). Always close with END.

Combining tables

Inner joins

Use it when the columns you need live in more than one table.

How it works

A join pairs rows from two tables wherever the ON condition is true, usually foreign key = primary key. An inner join keeps matched pairs only. A row with three matches appears three times.

Which rows each join keeps

Table A has keys 1, 2, 3. Table B has keys 2, 3, 4.

JoinKeys in the result
A JOIN B23
A LEFT JOIN B123 · 1 has NULLs for B
A RIGHT JOIN B234 · 4 has NULLs for A
A FULL JOIN B1234
A CROSS JOIN B3 × 3 = 9 pairs · no ON

Building a join

  1. List the columns the question wants.
  2. Find the tables that hold them (search bar or the Schemas page).
  3. Find the path between them in that schema's join list. Bridge tables sit in the middle.
  4. Add one JOIN … ON per table, each linking to a table already in the query.
  5. Add WHERE, then check the row count.
NeedSyntax
BasicFROM a JOIN b ON a.key = b.key
AliasesFROM Orders AS o JOIN Customers c ON …
Two-column keyON a.MatchID = b.MatchID AND a.GameNumber = b.GameNumber
Same column name both sidesJOIN b USING (CustomerID)
WHERE-style (older)FROM a, b WHERE a.key = b.key

Through a bridge table: entertainers and their styles

SELECT e.EntStageName, ms.StyleName
FROM EntertainmentAgencyExample.Entertainers AS e
JOIN EntertainmentAgencyExample.Entertainer_Styles AS es
  ON e.EntertainerID = es.EntertainerID
JOIN EntertainmentAgencyExample.Musical_Styles AS ms
  ON es.StyleID = ms.StyleID
ORDER BY e.EntStageName;
Traps
  • A comma join with no matching condition pairs every row with every row. Huge row count = missing ON/WHERE match.
  • Composite keys need every part in the ON, or rows multiply.
  • A column in both tables must be prefixed: c.CustomerID. Once a table has an alias, use the alias everywhere.
  • Skip joins you don't need: if one table has every column, use just that table.

Combining tables

Outer joins

Use it when the question says every / all / including those with none, or asks for rows that never matched.

How it works

LEFT JOIN keeps every row from the table in FROM (the left side). Where nothing matches, the right side's columns are NULL. RIGHT JOIN is the mirror image; FULL JOIN keeps unmatched rows from both.

NeedPattern
Keep all rows of AFROM a LEFT JOIN b ON …
Rows in A with no matchLEFT JOIN b ON … WHERE b.key IS NULL
Count per row, showing zerosLEFT JOIN b … COUNT(b.key) … GROUP BY
Filter B but keep all of APut the filter in ON, not WHERE (below)

Ingredients no recipe uses

SELECT i.IngredientName
FROM RecipesExample.Ingredients AS i
LEFT JOIN RecipesExample.Recipe_Ingredients AS ri
  ON i.IngredientID = ri.IngredientID
WHERE ri.RecipeID IS NULL;

ON vs. WHERE with outer joins

✓ All agents, plus only their 2018 bookings

FROM Agents a
LEFT JOIN Engagements e
  ON a.AgentID = e.AgentID
 AND e.StartDate >= '2018-01-01'

✗ Agents with no 2018 booking disappear

FROM Agents a
LEFT JOIN Engagements e
  ON a.AgentID = e.AgentID
WHERE e.StartDate >= '2018-01-01'

WHERE runs after the join. Unmatched rows have NULL there, NULL fails the test, and the LEFT JOIN quietly becomes an inner join.

Traps
  • Table order matters: the table you need all of goes in FROM.
  • In a chain, keep every later join LEFT too, or the NULL rows get dropped.
  • COUNT(*) counts an unmatched row as 1. Use COUNT(b.key) to get 0.
  • For "no match," test a column that can't be NULL in a real match (the key).

Combining tables

Self, cross & range joins

Use it when a table points to itself, you need one table twice, every combination, or a value matched to a range.

How it works

A join can use the same table twice if each copy has its own alias. The ON can be any true/false test, not only =. CROSS JOIN has no ON and returns every pair.

Self join: each subject with its prerequisite's name

SELECT s.SubjectCode, s.SubjectName,
       p.SubjectName AS prereq_name
FROM SchoolSchedulingExample.Subjects AS s   -- the subject
JOIN SchoolSchedulingExample.Subjects AS p   -- its prerequisite
  ON s.SubjectPreReq = p.SubjectCode;

Same lookup table twice: both teams in a match

SELECT tm.MatchID, odd.TeamName AS odd_lane, even.TeamName AS even_lane
FROM BowlingLeagueExample.Tourney_Matches AS tm
JOIN BowlingLeagueExample.Teams AS odd  ON tm.OddLaneTeamID  = odd.TeamID
JOIN BowlingLeagueExample.Teams AS even ON tm.EvenLaneTeamID = even.TeamID;

Range join with a driver table

SELECT p.ProductName, p.RetailPrice, r.PriceCategory
FROM SalesOrdersExample.Products AS p
JOIN SalesOrdersExample.ztblPriceRanges AS r
  ON p.RetailPrice BETWEEN r.LowPrice AND r.HighPrice;
Traps
  • A self join without two aliases is ambiguous. Name them for their role (s subject, p prerequisite).
  • CROSS JOIN rows = rows in A × rows in B. Filter afterwards if you only need some pairs.

Combining tables

UNION, INTERSECT, EXCEPT

Use it when you want to stack two result lists, or find what's in both or only one.

How it works

Joins add columns side by side; set operations add rows top to bottom. Each SELECT must return the same number of columns with matching types. Column names come from the first SELECT.

OperatorReturns
UNIONRows from either query, duplicates removed
UNION ALLRows from either query, duplicates kept (faster)
INTERSECTRows in both
EXCEPTRows in the first but not the second

Every city that has a customer or a vendor

SELECT CustCity AS city FROM SalesOrdersExample.Customers
UNION
SELECT VendCity FROM SalesOrdersExample.Vendors
ORDER BY city;
Traps
  • One ORDER BY, at the very end, using the first query's column names.
  • Fewer rows than expected? UNION removed duplicates. Use UNION ALL.
  • Add a label column to see where each row came from: SELECT 'Customer' AS source, ….

Summarizing

Aggregates & GROUP BY

Use it when the question says how many, total, average, highest, lowest, or per / for each.

How it works

An aggregate collapses many rows into one value. Without GROUP BY, the whole result becomes one row. With GROUP BY col, rows are sorted into buckets by that column and you get one row per bucket, with the aggregate computed inside each.

The rule: every column in SELECT must be in GROUP BY or inside an aggregate.

NeedSyntax
Count rowsCOUNT(*)
Count non-NULL valuesCOUNT(col)
Count unique valuesCOUNT(DISTINCT col)
Total / averageSUM(x)   ROUND(AVG(x), 2)
Smallest / largestMIN(x)   MAX(x) (also dates, text)
Total of a formulaSUM(QuotedPrice * QuantityOrdered)
Count only some rowsCOUNT(*) FILTER (WHERE x > 500)
Same, portableSUM(CASE WHEN x > 500 THEN 1 ELSE 0 END)
List in one cellSTRING_AGG(col, ', ' ORDER BY col)
Group by several columnsGROUP BY state, city

Products and average price per category

SELECT c.CategoryDescription,
       COUNT(*) AS products,
       ROUND(AVG(p.RetailPrice), 2) AS avg_price
FROM SalesOrdersExample.Products AS p
JOIN SalesOrdersExample.Categories AS c ON p.CategoryID = c.CategoryID
GROUP BY c.CategoryDescription
ORDER BY products DESC;

Every style, including ones no entertainer plays (count 0)

SELECT ms.StyleName, COUNT(es.EntertainerID) AS entertainers
FROM EntertainmentAgencyExample.Musical_Styles AS ms
LEFT JOIN EntertainmentAgencyExample.Entertainer_Styles AS es
  ON ms.StyleID = es.StyleID
GROUP BY ms.StyleName
ORDER BY entertainers DESC, ms.StyleName;
Traps
  • "must appear in the GROUP BY clause" = a plain column in SELECT. Add it to GROUP BY or aggregate it.
  • Grouping by name alone merges two people with the same name. Group by the ID too.
  • An extra column in GROUP BY splits groups further than you meant.
  • AVG of whole numbers gives long decimals. Wrap in ROUND(…, 2).

Summarizing

HAVING

Use it when you filter on a total: "customers with more than 40 orders," "styles played by at least 3 entertainers."

How it works

WHERE filters rows before grouping. HAVING filters groups after the aggregates are computed.

WHEREHAVING
FiltersRowsGroups
RunsBefore GROUP BYAfter GROUP BY
Can use aggregatesNoYes
ExampleWHERE OrderDate >= '2018-01-01'HAVING COUNT(*) > 40

Customers with more than 40 orders

SELECT CustomerID, COUNT(*) AS orders
FROM SalesOrdersExample.Orders
GROUP BY CustomerID
HAVING COUNT(*) > 40
ORDER BY orders DESC;
Traps
  • Repeat the aggregate in HAVING. The SELECT alias (orders) doesn't exist there yet.
  • Conditions on single rows belong in WHERE, even in a grouped query.

Summarizing

Window functions

Use it when you need a rank, a running total, or a group total next to each row.

How it works

Like an aggregate, but rows aren't collapsed. OVER (…) defines the window: PARTITION BY splits rows into groups, ORDER BY sets the order inside each group.

FunctionGives
ROW_NUMBER() OVER (ORDER BY x)1, 2, 3, 4 (no ties)
RANK() OVER (ORDER BY x DESC)1, 2, 2, 4 (ties share, then a gap)
DENSE_RANK() OVER (…)1, 2, 2, 3 (no gap)
NTILE(4) OVER (ORDER BY x)Quartile 1–4
SUM(x) OVER (ORDER BY d)Running total
AVG(x) OVER (PARTITION BY g)Group average on every row
LAG(x) / LEAD(x) OVER (ORDER BY d)Previous / next row's value

Place of each bowler within each game

SELECT BowlerID, MatchID, GameNumber, RawScore,
       RANK() OVER (PARTITION BY MatchID, GameNumber
                    ORDER BY RawScore DESC) AS place
FROM BowlingLeagueExample.Bowler_Scores;
Traps
  • You can't filter on a window function in WHERE. For "top 3 per group," compute it in a subquery or CTE, then WHERE place <= 3 outside.

Nesting

Subqueries

Use it when a filter depends on another query: "above average," "in the list of…," "has at least one…," "never…".

How it works

A query in parentheses inside another query. Where it sits decides what it must return: one value (after = or >, or in SELECT), one column (after IN), or a whole table (in FROM). A correlated subquery mentions the outer table, so it re-runs for each outer row.

NeedPattern
Compare to one valueWHERE x > (SELECT AVG(x) FROM t)
In a list from a queryWHERE id IN (SELECT id FROM t WHERE …)
Not in that listWHERE NOT EXISTS (…) (safer than NOT IN)
Has at least one related rowWHERE EXISTS (SELECT 1 FROM t WHERE t.id = outer.id)
Bigger than all / any> ALL (SELECT …)   > ANY (SELECT …)
A value per rowSELECT …, (SELECT COUNT(*) FROM t WHERE t.id = o.id)
A temporary tableFROM (SELECT …) AS t

Products priced above the average

SELECT ProductName, RetailPrice
FROM SalesOrdersExample.Products
WHERE RetailPrice > (SELECT AVG(RetailPrice)
                     FROM SalesOrdersExample.Products);

Recipes that use garlic (correlated EXISTS)

SELECT r.RecipeTitle
FROM RecipesExample.Recipes AS r
WHERE EXISTS (
  SELECT 1
  FROM RecipesExample.Recipe_Ingredients AS ri
  JOIN RecipesExample.Ingredients AS i ON ri.IngredientID = i.IngredientID
  WHERE ri.RecipeID = r.RecipeID          -- ties it to the outer row
    AND i.IngredientName = 'Garlic');
Traps
  • "more than one row returned by a subquery" → you used =; switch to IN.
  • IN (SELECT a, b …) fails. Select exactly one column.
  • NOT IN with a NULL in the list returns nothing.
  • Need columns from the other table in your output? Use a join instead.

Nesting

WITH (CTEs)

Use it when a query has a step you'd otherwise nest, like "first compute averages, then join them."

How it works

WITH name AS (…) defines a temporary result at the top of the query. The main SELECT then uses it like a table. Same result as a subquery in FROM, but easier to read.

Top five bowlers by average score

WITH bowler_avg AS (
  SELECT BowlerID, ROUND(AVG(RawScore), 1) AS avg_score
  FROM BowlingLeagueExample.Bowler_Scores
  GROUP BY BowlerID
)
SELECT b.BowlerFirstName, b.BowlerLastName, ba.avg_score
FROM bowler_avg AS ba
JOIN BowlingLeagueExample.Bowlers AS b ON b.BowlerID = ba.BowlerID
ORDER BY ba.avg_score DESC
LIMIT 5;
Traps
  • Several CTEs: one WITH, separated by commas: WITH a AS (…), b AS (…) SELECT ….
  • No semicolon between the CTE and the main SELECT. It's one statement.

Changing data

INSERT, UPDATE, DELETE

Use it when an assignment changes data. Work in the …Modify schemas.

How it works

These statements change rows and report a count (UPDATE 7) instead of returning results. pgAdmin saves each one immediately unless you're inside BEGIN. The safe habit: write the WHERE as a SELECT first, check the rows, then change SELECT to UPDATE or DELETE.

Test a change, look at it, undo it. Highlight all lines and run together.

BEGIN;
UPDATE SalesOrdersModify.Products
SET QuantityOnHand = QuantityOnHand + 10
WHERE CategoryID = 6;
SELECT ProductName, QuantityOnHand FROM SalesOrdersModify.Products WHERE CategoryID = 6;
ROLLBACK;   -- undo. Use COMMIT; to keep it.
NeedSyntax
Add one rowINSERT INTO t (a, b) VALUES (1, 'x');
Add several rowsVALUES (1, 'x'), (2, 'y');
Copy rows from a queryINSERT INTO t (a, b) SELECT a, b FROM s WHERE …;
See what changed… RETURNING *;
Change valuesUPDATE t SET a = a * 1.05, b = 'x' WHERE …;
Change using another table (subquery)UPDATE t SET … WHERE id IN (SELECT id FROM s WHERE …);
Change using another table (join)UPDATE t SET a = s.x FROM s WHERE t.id = s.id;
Delete rowsDELETE FROM t WHERE …;
Delete using another tableDELETE FROM t WHERE NOT EXISTS (SELECT 1 FROM s WHERE s.id = t.id);

Archive early orders: INSERT … SELECT

INSERT INTO SalesOrdersModify.Orders_Archive
       (OrderNumber, OrderDate, ShipDate, CustomerID, EmployeeID, OrderTotal)
SELECT OrderNumber, OrderDate, ShipDate, CustomerID, EmployeeID, OrderTotal
FROM SalesOrdersModify.Orders
WHERE OrderDate < '2017-10-01';

UPDATE from a join: reset quoted prices on one order

UPDATE SalesOrdersModify.Order_Details AS od
SET QuotedPrice = p.RetailPrice
FROM SalesOrdersModify.Products AS p
WHERE od.ProductNumber = p.ProductNumber
  AND od.OrderNumber = 1;
Traps
  • UPDATE or DELETE without WHERE changes every row.
  • Foreign keys set the order: insert parents before children; delete children (Order_Details) before parents (Orders).
  • After any error inside BEGIN, run ROLLBACK; before anything else.
  • Made a mess? Re-run LoadAllTextbookDatabases.sql to reset.

Fixing

Wrong row count

Use it when the query runs but doesn't match "Expected rows."

SymptomUsual causes
